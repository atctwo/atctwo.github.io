I've spent ~~too much~~ a small amount of time trying to get SMTP working with <abbr title="Queen's University Belfast">my university</abbr>'s Microsoft 365-managed email account.  I figured out exactly what combinations of settings to use to get it working with Thunderbird, and like [those](https://andrewbolster.info/2013/07/qub-email-settings-that-actually-work/), [those](https://ryanmcconville.com//blog/post/qub-email-settings), and [those](https://blogs.qub.ac.uk/screenshotsfromtheedge/static-pages/setting-up-student-office365-email-in-apple-mail/) who came before me, I thought it might be useful to publish my findings!

<!-- excerpt-end --> 

I've only tried these settings for my specific situation - I'm a PhD student using Thunderbird and Queen's email is provided through Microsoft 365 (ie: not on-premises) - so there's no guarantee that they'll work for everyone.  But I hope someone finds them useful anyway!

Also, these systems seem to change often enough for multiple generations of students to write blog posts on them.  This post was written in May 2026, so it will likely have changed if you're from the future!

# SMTP and IMAP
I've been using SMTP (for outgoing) and IMAP (for incoming) with only one or two minor issues for a while now.  Here's what I've found works:

<div class="cols rainbow-border">
<div class="no_toc_section rainbow-border" markdown="1">

### IMAP (Incoming)
- Server: `outlook.office365.com:993` [^1]
- Security: SSL/TLS
- User name: `<student num>@ads.qub.ac.uk`
- Authentication method: OAuth2

</div>

<div class="no_toc_section rainbow-border" markdown="1">

### SMTP (Outgoing)
- Server: `smtp.office365.com:587` [^1]
- Security: STARTTLS
- User name: `<student num>@ads.qub.ac.uk`
- Authentication method: OAuth2

</div>
</div>
<br>

[^1]: previous work suggested `smtp.qub.ac.uk` and `imap.qub.ac.uk` as the servers but these seem to no longer work

Note that the user name should be your `<student num>@ads.qub.ac.uk`, rather than your `<name>@qub.ac.uk` address.  I've had success fetching mail with IMAP using the latter, but SMTP just fails to authenticate.

If you're using Thunderbird, it should be able to automatically fetch the correct server config based on the `@ads.qub.ac.uk` part of your address.

{% include admonition.html type="info" title="Exchange Web Services (EWS)" %}

Another option if your email client supports it is good ol' Exchange Web Services!  But in reality this won't be an option for long since Microsoft will be [disabling EWS for all organisations](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/deprecation-of-ews-exchange-online) starting October 2026 (at least for M365 tenants).  This is kind of a shame since Thunderbird actually [added native EWS support](https://blog.thunderbird.net/2025/11/thunderbird-adds-native-microsoft-exchange-email-support/) in November 2025[^2] :(

The recommended alternative is Microsoft's [Graph API](https://learn.microsoft.com/en-us/graph/overview), but it doesn't look like there are many email clients that support it - although it seems that Thunderbird is [actively working on it](https://blog.thunderbird.net/2026/03/thunderbird-monthly-development-digest-march-2026/#:~:text=Exchange%20Email%20Support)!  In the meantime, SMTP and IMAP should keep working (***I Hope***).

{% include admonition_end.html %}

[^2]: [This Thunderbird dev post](https://blog.thunderbird.net/2024/04/adventures-in-rust-bringing-exchange-support-to-thunderbird/) about bringing EWS support mentions that they added it despite the looming deprecation, because there's a lot of users still using EWS with on-prem installs of Exchange Server


# Authentication
I initially couldn't get the above settings to work, despite other people having success with them.  I eventually realised it was because Queen's had disabled the ([now-deprecated](https://techcommunity.microsoft.com/blog/exchange/updated-exchange-online-smtp-auth-basic-authentication-deprecation-timeline/4489835)) Basic authentication scheme for SMTP.  Everything has to go through [OAuth2](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth) now.

OAuth2 works by providing every client (like Thunderbird) a **client ID** and sometimes a **client secret**.  These can pretty easily be obtained by [registering your application](https://www.emailarchitect.net/eaoauth/kb/azure_application_pop_imap_grant.aspx) on Azure Portal, but a consequence of this system is that (most) tenants, including Queen's, *require **all** client applications to be approved by an admin*.

Thankfully, Thunderbird's client is already approved by Queen's, so I've had no issues using the standard OAuth2 authentication flow with it.  But other clients with their own client IDs will need to be approved manually, and I haven't had much luck with this.

    <img src="/assets/images/posts/qub-smtp/k9.png" alt="Screenshot of the OAuth2 login flow for unapproved clients, showing the approval request form.  There's a list of all the endpoints the client is requesting access for, as well as a text box for the user to provide a justification for the request">
    <figcaption>I had trouble setting up email on my phone with K9 Mail</figcaption>
</figure>

Having said this, some email clients like [Evolution](https://gitlab.gnome.org/GNOME/evolution/-/wikis/home) allow you to specify a custom client ID.  My advice is to *not* obtain the client ID of a trusted open-source application like Thunderbird and use that, effectively making it look like it was actually Thunderbird from M365's perspective.  Definitely don't do this...


# Shared Mailboxes
I've also spent too much time trying to get shared mailboxes accessible through Thunderbird, such as those provided for Queen's societies.  The configuration I found that worked is the same as the single-user method described above, except with `<student num>@ads.qub.ac.uk` replaced with `<mailbox>@qub.ac.uk` **for IMAP only**.  The SMTP configuration should be the same as a single-user setup.

<div class="cols rainbow-border">
<div class="no_toc_section rainbow-border" markdown="1">

### IMAP (Incoming)
- Server: `outlook.office365.com:993`
- Security: SSL/TLS
- <span class="mark">Username: <code>&lt;mailbox&gt;@qub.ac.uk</code></span>
- Authentication method: OAuth2

</div>

<div class="no_toc_section rainbow-border" markdown="1">

### SMTP (Outgoing)
- Server: `smtp.office365.com:587`
- Security: STARTTLS
- Username: `<student num>@ads.qub.ac.uk`
- Authentication method: OAuth2

</div>
</div>
<br>

Additionally, you should authenticate during the OAuth2 login flow as yourself (ie: your personal account).  The login flow might not give you the option to log in as anyone other than the mailbox account, but I've found that if you deliberately enter the wrong password it will then give you an option to log in with a different account.
